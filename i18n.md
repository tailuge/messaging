# Internationalization (i18n)

One module: **`src/client/i18n.js`**. It is bundled into `lobby.js` and `arena.js`, so there is no
separate file to copy at build time.

## Design

**English strings are the keys.** There is no `en` dictionary — English is the identity map, so the
source string and its key can never drift apart. A missing translation falls back to the key:

```js
i18n.t('Accept')                       // "Accept"  (en, or a locale with no entry)
i18n.t('Challenge {name}', { name })   // "Challenge Alice" / "Alice에게 도전"
```

Only non-English locales are stored, which is what makes partial translation safe: an untranslated
string renders readable English rather than a blank control.

Shipped locales are `en`, `ko`, `ja`, `tr`. Translations currently need review by a native speaker.

## API

```js
import { i18n, I18nElement } from './i18n.js';

i18n.t(key, params)   // translate; params interpolate {placeholder}
i18n.lang             // current code, e.g. 'ko'
i18n.languages        // [{ code, label }] for a language picker
i18n.set(code)        // switch language; persists and notifies subscribers
i18n.onChange(fn)     // subscribe; returns an unsubscribe function
```

`I18nElement` extends `StoreElement`, so it re-renders on a **userStore change or a language
change**. Extend it for any component whose `render()` calls `i18n.t` — most lobby panels need both,
and one base class covers them. Non-Lit code can use `i18n.onChange` directly.

## Language resolution

Resolved once at load, in this order:

1. `?locale=` query parameter
2. `localStorage['locale']` (the earlier keys `lang` and `selector_lang` are still read as fallbacks)
3. the browser's preferred languages, prefix-matched (`ko-KR` → `ko`)
4. English

An explicit `?locale=` is **authoritative**: a code we do not ship resolves to English rather than
falling through to the browser, so an override is always under the tester's control. It is
deliberately **not persisted**, so a shared test link cannot overwrite a visitor's saved choice.

The resolved locale is mirrored to `document.documentElement.lang` for assistive technology and for
`:lang()` styling hooks.

## Testing a locale

```
lobby.html?locale=ko          lobby.html?locale=ja          lobby.html?locale=tr
```

The parameter name matches the sibling `billiards` project. Or, without a URL parameter:

```js
localStorage.setItem('locale', 'ko');
location.reload();
```

The selector modal also has a language picker that calls `i18n.set`.

## Adding a language

1. Add an entry to `LOCALES`.
2. Add a `TRANSLATIONS` dictionary for it, keyed by the English source strings.

## Coverage

Wired so far:

| Area | File | Strings |
| --- | --- | --- |
| Variant selector modal | `selector-modal.js` | labels, game/rule names, Cancel, Play |
| Challenge banner | `challenge-banner.js` | Accept, Decline, Cancel, Dismiss, banner copy |
| Challenge picker | `challenge-modal.js` | Challenge {name}, Cancel, Send message |
| Player list | `user-list.js` | Challenge |

Not yet wired: challenge-banner option labels (`Race to`, `Reds`, `Shot clock`, …), the rest of
`challenge-modal.js`'s game/rule names, and the remaining lobby panels.

## Fonts

Not handled. CJK glyphs rely on the system font stack; `documentElement.lang` is now set, so a
`:lang(ko)` font-family rule is the hook if one is needed later.
